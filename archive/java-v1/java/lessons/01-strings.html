What is a String?

A String is a sequence of characters, such as "Hello", "42" or "". In Java it is an object of the class java.lang.String. It is not a primitive like int or char.

"Hello"

Indexes start at 0. length() is 5, so the last index is length() - 1 = 4.

Memory and the String Pool

The String pool keeps one shared copy of each literal. Since Java 7 the pooled String objects live in the ordinary heap; the lookup table itself (HotSpot's StringTable) is native JVM memory. Step through the code below and watch where each variable points.

💡 Remember itThe String pool is a shared sticker book. Every "hi" literal in your program uses the same sticker; new String("hi") prints a fresh copy that is not in the book.
String pool
Heap (outside the pool)
  • Two equal literals share one object, so == is true.
  • new String(...) always creates a separate object. intern() returns the pooled copy.
  • Compile-time constants ("hel" + "lo", or a final variable plus a literal) are joined by the compiler. Runtime concatenation creates a new object.
Interview classic: How many objects does new String("hello") create? Up to two: the pooled literal (if it isn't already there) plus one new heap object.
Rule: never compare content with ==. Use equals(). The == results only show where objects live.
Interview answer

The String pool is a JVM-wide table of unique String objects. Every String literal is resolved through it, so equal literals share one object, which saves memory and makes == true between them. Since Java 7 the pool lives in the main heap, so pooled Strings can be garbage-collected. new String("x") always creates a separate heap object, and intern() returns the pooled copy, adding one if needed.

Follow-ups
  • Why not intern everything? — The pool is a hash table that starts with 65536 buckets (-XX:StringTableSize) and grows as needed since JDK 11, lookups cost time, and most runtime Strings are short-lived; interning helps only when there are many duplicates that live long.
  • Is "a" + "b" pooled? — Yes, javac folds constant expressions into the literal "ab". With a non-final variable, the result is a new heap String.
  • Where was the pool before Java 7? — In PermGen, which had a fixed size, so heavy interning could cause OutOfMemoryError: PermGen space.
  • Should you compare with == because of the pool? — No. Strings built at runtime (input, JSON, DB values) are not pooled; always use equals.
04

Immutability

Once created, a String's characters never change. Methods such as toUpperCase, replace, trim and substring return a new String. If you don't keep the result, it is lost.

The same holds for every "changing" method: name.toUpperCase() leaves "java" untouched and returns a new "JAVA". Write name = name.toUpperCase(); to move the variable to it.

Why Java made String immutable

1 · Pool safety

Many variables can share one object without affecting each other.

2 · Security

Paths, URLs and class names can't change after they are checked.

3 · Thread safety

Strings can be shared across threads with no locks.

4 · Cached hashCode

It is computed once, which makes Strings fast HashMap keys.

Do you need text that changes? Use StringBuilder, which is mutable (section 08).

Interview answer

A String's content can never change after it is created; every "modifying" method returns a new String. Java designed it that way so Strings can be shared safely in the pool, used as HashMap keys with a cached hash, passed between threads without locking, and trusted in security checks such as file paths, URLs and class names. The cost is extra objects when you modify text repeatedly, which is what StringBuilder is for.

Follow-ups
  • How is immutability enforced? — The class is final, the value array is private final, no method writes to it, and it is never handed out without copying.
  • Is final String s the same thing? — No. final fixes the variable's reference; immutability is a property of the object.
  • Why can the hash be cached? — The content can't change, so the hash can't either; it is computed once and stored in the hash field.
  • Why char[] for passwords? — You can overwrite a char[] after use; an immutable String stays in memory until it is collected.

06

Characters, indexes and length

  • Indexes run from 0 to length() - 1. A bad index throws StringIndexOutOfBoundsException.
  • s.length() is a method, arr.length is a field, and list.size() is for collections.
  • A char is a 16-bit number: 'a' + 1 is 98, (char) ('a' + 1) is 'b', '7' - '0' is 7, and 'd' - 'a' is 3. The last one is the basis of the int[26] counting trick.
  • Useful values: '0' = 48, 'A' = 65, 'a' = 97, space = 32. Lower case minus upper case = 32.

Building Strings: +, StringBuilder, StringBuffer

+ is evaluated left to right. "Total: " + 1 + 2 gives "Total: 12", while "Total: " + (1 + 2) gives "Total: 3".

This visualisation needs JavaScript.

+= in a loop is O(n²). Each step copies everything built so far. Java 9+ optimises a single a + b + c expression, but not a loop. Use one StringBuilder instead.
StringStringBuilderStringBuffer
MutableNoYesYes
Thread-safeYes (immutable)NoYes (synchronized)
Building speedSlow in loopsFastestSlower (locking)
Use whenText is fixedDefault for buildingSeveral threads share one buffer

Main StringBuilder methods are append, insert, delete, deleteCharAt, replace, reverse, setCharAt, setLength and toString. Most return this, so you can chain them. The default capacity is 16 and it grows to about 2×; pre-size it with new StringBuilder(n). For joining, use String.join, StringJoiner or Collectors.joining.

Interview answer

Use + for a few fixed pieces, and a StringBuilder when you build text in a loop: each += copies the whole String so far, which is O(n²), while a builder appends into one growing buffer. StringBuffer is the same API with every method synchronized; it is a leftover from Java 1.0, and you rarely need it because builders are usually local to one thread. For joining collections, String.join, StringJoiner or Collectors.joining read better.

Follow-ups
  • Doesn't the compiler use a builder for + anyway? — For one expression, yes (or invokedynamic on Java 9+), but in a loop it creates a new one on every iteration.
  • Is StringBuffer fully thread-safe? — Each call is, but a sequence such as check-length-then-append is not atomic without your own lock.
  • How do you avoid regrowth? — Pass an expected capacity: new StringBuilder(expectedSize).

15 interview questions

Answer each one in your head before you open it.

01What is a String? Is it a primitive?
An object of the final class java.lang.String: an immutable sequence of UTF-16 chars. It is not a primitive, but the language gives it special support (literals, +, switch).
02Why is String immutable?
Pool sharing is safe, checked values can't change (security), it is thread-safe with no locks, the hashCode can be cached for fast HashMap keys, and class loading is reliable.
03What is the String pool? Where is it?
A table holding one shared copy of each literal (and of each interned String). It moved from PermGen to the main heap in Java 7.
04What is the difference between == and equals()?
== compares references and equals() compares characters. Always use equals for content.
05How many objects does new String("abc") create?
One or two: the pooled literal (if it isn't already there) plus one new heap object.
06What does intern() do?
It returns the canonical pooled copy with the same content, adding it if it is missing.
07String vs StringBuilder vs StringBuffer?
String is immutable. StringBuilder is mutable, not synchronized, and fastest. StringBuffer is mutable and synchronized, so it is slower.
08Why is += in a loop slow?
Each iteration copies everything built so far, which is O(n²) in total. One StringBuilder makes it O(n).
09Why is "a" + "b" == "ab" true, but a + "b" == "ab" false?
Literal concatenation is a compile-time constant, so it is pooled. With a non-final variable, the String is built at runtime as a new object. A final variable makes the result true again.
10Why is char[] preferred over String for passwords?
A String stays in memory until garbage collection and can't be wiped. A char[] can be overwritten right after use, and it is less likely to be logged by accident.
11Can String be extended? Why is it final?
No. Making it final protects immutability and security, and it allows JVM optimisations.
12How does compareTo work?
It returns the difference of the first pair of characters that differ. If one String is a prefix of the other, it returns the length difference. The result is 0 when the Strings are equal.
13What are Compact Strings?
Since Java 9, Strings store a byte[] plus a coder. LATIN-1 text uses 1 byte per char, which halves the character storage (the object header and fields stay the same, so "hello" goes from 56 to 48 bytes).
14Why does "hi😀".length() return 4?
length() counts UTF-16 code units, and the emoji is a surrogate pair. codePointCount gives 3.
15How does switch work with Strings?
The compiler switches on hashCode(), then calls equals() to confirm. A null selector throws NullPointerException (unless there is a case null, Java 21+).

5 takeaways

  • A String is an immutable object: every "change" returns a new String, so reassign the result.
  • Compare content with equals (null-safe as "lit".equals(x)); == only tells you if it is the same object.
  • Literals are pooled and shared; new String always makes a new heap object; intern() returns the pooled one.
  • Build text in loops with a StringBuilder; += copies everything each time.
  • split and replaceAll take regex, substring's end is excluded, and an emoji is 2 chars.
