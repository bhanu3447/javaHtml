## How the pages work (all CSS/JS in `assets/`)
- Section text below written as "the page" means the course as a whole; each widget lives on the page that holds its section. Google Fonts (Inter, Inter Tight, JetBrains Mono).
- **Multi-page v8 (2026-10-20):** `course.js` starts with `COURSE`, `PAGE` (body `data-page`: `home`, `l00`…, `practice`), `ROOT` (course folder URL from `document.currentScript`), `SECP` (section id → page), `LESSONS`, `pageUrl(p,id)`, `secUrl(id)`. Every page-specific widget is guarded (`if($("#poolviz"))…`), so one script serves every page. The sidebar lists the whole course from `COURSE`; other pages' groups are folded (`.tg.fold`) until you search (`#toc.searching`); items carry `data-id`, group headers `data-l`. Nav `.links` and the header `.pager` (← previous / next →) are filled from `COURSE`. Progress/review/bookmarks use all lessons' sections (footers only on the current page); the mock interview reads `COURSE.qa` and "Open in the lesson" opens the other page; the palette adds a "Pages" group and opens tools/sections on other pages. Full-text search covers the current page only. CSS block `/* multi-page v8 */` at the end of `course.css`. The old single file is not kept.
- **Theme:** CSS variables on `:root`, with a dark mode set by `prefers-color-scheme` and by `[data-theme]`. The ◐ button opens the theme picker (Auto · time + 10 themes; see "Enhancements v3" and "Motion v4").
- **Code blocks:** they are written as `<script type="text/x-java" data-file="X.java" data-hl="7-9">…</script>`, and the JS turns each one into an editor. To add code to the page, add one of these blocks; `data-hl` lists lines to highlight.
- **Editor:** CodeMirror **5.65.16** from cdnjs (core, clike mode, show-hint, matchbrackets, closebrackets, active-line, comment). The CodeMirror CSS is inlined in `<style>`. If the CDN fails, the page falls back to static highlighted `<pre>` blocks using the `hl()` function.
- **Suggestions engine** (inside the JS, in the block starting "code blocks → live editors"):
  - `MEM` holds instance methods per type (String, StringBuilder, StringBuffer, PrintStream, arrays as `"[]"`, Object). `STAT` holds static members (String, Character, Arrays, Math, System, Objects, Integer). Entries are `[name, params|null-for-field, returnType, doc]`, and the list order is the order shown after a dot.
  - `typeAt()` works out the receiver type: string literals, `new X(...)`, chained calls, `arr[i]`, declared variables (`varType`), and methods declared in the file (`methodsIn`).
  - `SNIPS` holds the snippets: sout, psvm, fori, forr, foreach, swap, ifnull, sb, tca. In a snippet body, `$0` marks where the cursor goes.
  - `rank()` orders matches: prefix first, then case-insensitive prefix, then camelCase humps, then substring matches (3 or more characters, variables and methods only). An exact match is hidden.
  - Suggestions open automatically on `inputRead` when the Suggestions switch is on. `Ctrl+Space` always opens them.
  - The **Suggestions switch** applies to every editor at once.
- **Editor chrome:** window dots, file name, "● edited" marker, Suggestions switch, Reset, Copy, and a status bar showing Ln/Col and the doc for the highlighted suggestion.
- **Playground:** `#pg`, with tasks in the `PG` array (`{n, f, o, c}` = name, file, expected output, code). The tasks are Count vowels, Anagram, Capitalize words, Letter frequency, Compress, Pool predictions and Blank. Every starter compiles. Drafts are saved in the browser.
- **String Pool visualizer** (`#poolviz`): `POOL_STEPS` holds `{c: code, run(S): S.obj(id,val,"pool"|"heap") / S.v(name,id), m: message}`. It renders the pool and heap objects, the variable chips, and a table of `s1 ==` / `equals` results.
- **Method explorer** (`#mx`): `MX` holds `[label, args[name,type,default], fn(s,args)→{r,t,hl,n}]`. It mimics Java, including the exceptions, the trailing-empty rule in `jsplit`, `jcompare` and `hashCode`. These were checked against real Java.
- **Character inspector** (`#ci`): it shows each UTF-16 unit (index, char, number, `\uXXXX`, surrogate flag) and the stats for `length()`, code points, and UTF-8 bytes.
- **localStorage keys** (always wrapped in try/catch): `js1-theme`, `js1-suggest`, `js1-pg-<i>`, `js1-pg-last`, `js1-chk` (indexes into `CK`, so new checklist items are only ever **appended**), `js1-done` (`{sectionId: {t, r, s}}`: learned time, last review, stage 0–3), `js1-bm` (bookmarks), `js1-qz-<lesson>` (`{questionIndex: chosenOption}`), `js1-mock` (`{secId:qNum → {r: 1 nailed|2 shaky|3 missed, t}}`), `js1-mock-cfg` (`{ls, weak, n, t}`), `js1-anim` ("0" = background animation off), `js1-fx` ("1" = decorative effects on; default paused, since 2026-10-23), `js1-motion` ("0" = **all animations off**, the nav ⏸/▶ button). `js1-theme` now holds a theme id or "" (= system). The prefix was changed from `sr2-` so old reversal drafts don't load.
- Editors inside closed `<details>` are refreshed when they are shown (`refreshIn`). The `#tabs` handler is guarded, because Lesson 01 has no tabs.
- **Lesson 02 on the page:** band `#deep`, sections `#d-*` (D1–D13), object-count spoilers `.spoil`, StringBuilder capacity simulator `#capviz` (rule `max(old*2+2, needed)`). Details: `KB.md` → "Appendix — page effects internals".

## How the pages work (all CSS/JS in `assets/`)
- Section text below written as "the page" means the course as a whole; each widget lives on the page that holds its section. Google Fonts (Inter, Inter Tight, JetBrains Mono).
- **Multi-page v8 (2026-10-20):** `course.js` starts with `COURSE`, `PAGE` (body `data-page`: `home`, `l00`…, `practice`), `ROOT` (course folder URL from `document.currentScript`), `SECP` (section id → page), `LESSONS`, `pageUrl(p,id)`, `secUrl(id)`. Full-text search covers the current page only. CSS block `/* multi-page v8 */` at the end of `course.css`. The old single file is not kept.
- **Theme:** CSS variables on `:root`, with a dark mode set by `prefers-color-scheme` and by `[data-theme]`. The ◐ button opens the theme picker (Auto · time + 10 themes; see "Enhancements v3" and "Motion v4").
- **Code blocks:** they are written as `<script type="text/x-java" data-file="X.java" data-hl="7-9">…</script>`, and the JS turns each one into an editor. To add code to the page, add one of these blocks; `data-hl` lists lines to highlight.
- **Editor:** CodeMirror **5.65.16** from cdnjs (core, clike mode, show-hint, matchbrackets, closebrackets, active-line, comment). The CodeMirror CSS is inlined in `<style>`. If the CDN fails, the page falls back to static highlighted `<pre>` blocks using the `hl()` function.
- **Suggestions engine** (inside the JS, in the block starting "code blocks → live editors"):
  - `MEM` holds instance methods per type (String, StringBuilder, StringBuffer, PrintStream, arrays as `"[]"`, Object). `STAT` holds static members (String, Character, Arrays, Math, System, Objects, Integer). Entries are `[name, params|null-for-field, returnType, doc]`, and the list order is the order shown after a dot.
  - `typeAt()` works out the receiver type: string literals, `new X(...)`, chained calls, `arr[i]`, declared variables (`varType`), and methods declared in the file (`methodsIn`).
  - `SNIPS` holds the snippets: sout, psvm, fori, forr, foreach, swap, ifnull, sb, tca. In a snippet body, `$0` marks where the cursor goes.
  - `rank()` orders matches: prefix first, then case-insensitive prefix, then camelCase humps, then substring matches (3 or more characters, variables and methods only). An exact match is hidden.
  - Suggestions open automatically on `inputRead` when the Suggestions switch is on. `Ctrl+Space` always opens them.
  - The **Suggestions switch** applies to every editor at once.
- **Editor chrome:** window dots, file name, "● edited" marker, Suggestions switch, Reset, Copy, and a status bar showing Ln/Col and the doc for the highlighted suggestion.
- **Playground:** `#pg`, with tasks in the `PG` array (`{n, f, o, c}` = name, file, expected output, code). The tasks are Count vowels, Anagram, Capitalize words, Letter frequency, Compress, Pool predictions and Blank. Every starter compiles. Drafts are saved in the browser.
- **String Pool visualizer** (`#poolviz`): `POOL_STEPS` holds `{c: code, run(S): S.obj(id,val,"pool"|"heap") / S.v(name,id), m: message}`. It renders the pool and heap objects, the variable chips, and a table of `s1 ==` / `equals` results.
- **Method explorer** (`#mx`): `MX` holds `[label, args[name,type,default], fn(s,args)→{r,t,hl,n}]`. It mimics Java, including the exceptions, the trailing-empty rule in `jsplit`, `jcompare` and `hashCode`. These were checked against real Java.
- **Character inspector** (`#ci`): it shows each UTF-16 unit (index, char, number, `\uXXXX`, surrogate flag) and the stats for `length()`, code points, and UTF-8 bytes.
