THE BASICS, IN ORDER2
What an annotation is, and who reads it.
An annotation is a label you attach to a class, method, field or parameter (@Service, @GetMapping…). By itself it does nothing: it is metadata. At startup Spring reads those labels with reflection and acts on them: creates objects, wires them together, maps URLs to methods. The objects Spring creates and manages are called beans, and the thing that holds them is the container (the ApplicationContext).


ANNOTATION
A label with meaning
@Target says where it may go (class, method, field, parameter) and @Retention(RUNTIME) keeps it in the compiled class so Spring can read it while the app runs. Every Spring annotation is just a Java annotation like that.
SPRING FRAMEWORK
The container
Spring's job is Inversion of Control: you declare what you need, the container builds the objects and injects their dependencies. You never call new UserService(new UserRepository()) yourself.
SPRING BOOT
The opinionated start
Boot adds auto-configuration (sees a JDBC driver on the classpath → configures a DataSource), an embedded Tomcat and sensible defaults, so one @SpringBootApplication class is a runnable app.


01Scan@ComponentScan walks your package for classes marked @Component, @Service, @Repository, @Controller, @Configuration.
02Create beansOne instance of each (singleton), plus the return values of every @Bean method and whatever auto-configuration adds.
03InjectConstructor parameters are filled by type (@Qualifier by name). @Value and @ConfigurationProperties pull in properties. @PostConstruct runs.
04Map requestsEvery @RequestMapping/@GetMapping method is registered in the DispatcherServlet's table. Tomcat starts on 8080. Ready.

HOW @TRANSACTIONAL, @CACHEABLE AND @ASYNC WORK3
The bean you get is a proxy.
When a bean carries one of these annotations, the container does not hand out your object. It hands out a proxy: a generated subclass that wraps your object, does the extra work (open a transaction, check a cache, switch threads) and then calls your method. Understanding this one picture explains the three most-asked interview traps.

BEANS AND DEPENDENCY INJECTION10
One family of stereotypes, one container.
Every stereotype is @Component underneath. The specialisations add intent (and, for @Repository, exception translation; for @RestController, @ResponseBody). The container creates one bean per class and hands each one the beans its constructor asks for.
