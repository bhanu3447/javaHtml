THE BASICS, IN ORDER2
What an annotation is, and who reads it.
An annotation is a label you attach to a class, method, field or parameter (@Service, @GetMapping…). By itself it does nothing: it is metadata. At startup Spring reads those labels with reflection and acts on them: creates objects, wires them together, maps URLs to methods. The objects Spring creates and manages are called beans, and the thing that holds them is the container (the ApplicationContext).


ANNOTATION
A label with meaning
@Target says where it may go (class, method, field, parameter) and @Retention(RUNTIME) keeps it in the compiled class so Spring can read it while the app runs. Every Spring annotation is just a Java annotation like that.
SPRING FRAMEWORK
The container
Spring's job is Inversion of Control: you declare what you need, the container builds the objects and injects their dependencies. You never call new UserService(new UserRepository()) yourself.
SPRING BOOT
The opinionated start
Boot adds auto-configuration (sees a JDBC driver on the classpath → configures a DataSource), an embedded Tomcat and sensible defaults, so one @SpringBootApplication class is a runnable app.


01Scan@ComponentScan walks your package for classes marked @Component, @Service, @Repository, @Controller, @Configuration.
02Create beansOne instance of each (singleton), plus the return values of every @Bean method and whatever auto-configuration adds.
03InjectConstructor parameters are filled by type (@Qualifier by name). @Value and @ConfigurationProperties pull in properties. @PostConstruct runs.
04Map requestsEvery @RequestMapping/@GetMapping method is registered in the DispatcherServlet's table. Tomcat starts on 8080. Ready.

HOW BOOT CONFIGURES ITSELF5
Auto-configuration: where the defaults come from.
You add a starter and suddenly there is a DataSource, an embedded Tomcat and a JSON converter. It is not magic: Boot reads a list of candidate configuration classes from your jars and keeps the ones whose conditions are true. Your own beans always win.


HOW @TRANSACTIONAL, @CACHEABLE AND @ASYNC WORK6
The bean you get is a proxy.
When a bean carries one of these annotations, the container does not hand out your object. It hands out a proxy: a generated subclass that wraps your object, does the extra work (open a transaction, check a cache, switch threads) and then calls your method. Understanding this one picture explains the three most-asked interview traps.

FILTERS AND INTERCEPTORS9
A filter wraps everything; an interceptor wraps your handler.
Two places to run code around every request, often confused in interviews. A Filter belongs to the Servlet container and runs before Spring MVC; a HandlerInterceptor runs inside Spring MVC and knows which controller method was chosen.


SPRING SECURITY10
Who are you, and are you allowed? 401 versus 403.
Spring Security is a chain of servlet filters in front of the DispatcherServlet. Follow a request with a JWT through it: CORS, CSRF, authentication (who are you? else 401) and authorization (may you do this? else 403), until your controller receives the user.

PAGINATION AND SORTING15
Never return the whole table.
Spring Data turns ?page=1&size=3&sort=name into a Pageable, runs a LIMIT/OFFSET query plus a count, and returns a Page with the rows and the totals.


CALLING OTHER SERVICES16
RestClient, WebClient, HTTP interfaces and retries.
Services call each other over HTTP. Pick a client, always set timeouts, retry what is safe to retry, and have a fallback for when the other side stays down.


MESSAGING WITH KAFKA17
Events instead of calls: topics, partitions, consumer groups.
With Kafka a service publishes an event and moves on; any number of other services consume it in their own time. Follow one event from KafkaTemplate.send() to a @KafkaListener, and see what happens when processing fails.


OBSERVABILITY18
Logs, metrics, traces and health.
In production you cannot attach a debugger. Logs say what happened, metrics say how much and how fast, traces follow one request across services, and health checks tell the platform whether to send traffic.
