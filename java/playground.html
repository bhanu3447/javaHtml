How it works

  
A browser can't run Java, so Visualize uses a small Java interpreter written in JavaScript (jvm-lite.js). It understands most of what you write in the course and on interview whiteboards: classes, inheritance, interfaces, lambdas, records, enums, generics, arrays, Strings, StringBuilder, the collections (ArrayList, LinkedList, HashMap, TreeMap, HashSet, ArrayDeque, Stack, PriorityQueue), Scanner, printf, streams and exceptions. Its output was checked against JDK 25 on 72 programs, including HashMap iteration order, the Integer cache, the String pool and stack traces. Threads, files and reflection are not supported: the visualizer names the line and suggests Run, which sends the code to a real JDK.

  
Arrows are references. A faded box is unreachable: nothing points to it any more, so the garbage collector may free it; on a System.gc() step the collector frees those boxes and they disappear (real Java decides by itself when to collect, so the visualizer only collects when the program asks). The Classes area shows each class when it is loaded, with its static fields and methods: hover a class to light up every object built from it. Variables show as <local1> in a NullPointerException because java File.java compiles without debug names, exactly like the real JVM.
