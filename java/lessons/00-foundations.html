Java, the JDK and the two kinds of types

The words every later lesson uses, explained once and simply: what Java is, how a program is compiled and run, what the JDK, JRE and JVM are, and the difference between a primitive and a reference type.

LESSON 00

Before Strings and objects: the ground they stand on

Six short sections. Each one is a picture, a few lines of code with their output, and the one idea to keep.

01

What is Java?

Java is a programming language and a platform. You write text in a .java file. A compiler turns it into bytecode, a .class file that is the same on every computer. A program called the JVM (Java Virtual Machine) reads that bytecode and runs it. That is "write once, run anywhere".

The two commands
javac Hello.java      // compile: makes Hello.class (bytecode)
java Hello            // run: starts the JVM, which calls main
java Hello.java       // Java 11+: compile and run in one step
Compile errors stop at the first command; run-time errors happen in the second.

Every program in this course starts the same way: a public class with the file's name, and a main method where the JVM begins. Lesson 02 explains what a class is; for now it is the box the program lives in.

02

JDK, JRE and JVM

Three names, one set of nested boxes. The JVM runs bytecode. The JRE (Java Runtime Environment) is the JVM plus the class library (String, System, ArrayList…), enough to run programs. The JDK (Java Development Kit) is the JRE plus the tools to write programs: javac, jshell, jar, a debugger.

You want to…You needWhy
Write and compile JavaJDKOnly the JDK has javac
Run a finished .jar or .classJRE (inside the JDK)The JVM plus the library are enough
Run bytecode on a new machineJVM for that OSThe bytecode never changes; the JVM is the part built per OS
Check what is installed
java -version      // the runtime: prints the JVM version
javac -version     // the compiler: only exists when the JDK is installed
If javac is "not recognised", you have a runtime but not the kit: install a JDK.
💡 Remember itA car needs an engine (the JVM) and a body with seats (the JRE: the library). The factory that builds cars needs all of that plus the tools (the JDK). You are the factory, so you install the JDK.
03

What the JVM does while your program runs

When you type java Hello, the JVM loads the class, finds main and starts running it. It keeps everything in three areas. You will meet them again in every memory question, so here they are once, simply.

Two kinds of error
int x = "5";             // compile error: incompatible types: String cannot be converted to int
                         // javac stops here; no .class file is written

int[] a = new int[2];
a[5] = 1;                // runs, then: ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 2
                         // the JVM stops the program
The compiler checks types before anything runs; the JVM checks what only happens at run time.
04

Primitive vs reference types

Every variable in Java is one of two kinds. A primitive variable holds the value itself: a number, a character, true or false. There are exactly eight. A reference variable holds the address of an object on the heap: a String, an array, anything made with new. Everything that is not one of the eight is a reference type.

Examples
Integer division
System.out.println(7 / 2);     // 3     int / int drops the fraction
System.out.println(7 / 2.0);   // 3.5   one double makes it decimal
System.out.println(7 % 2);     // 1     the remainder
Two whole numbers give a whole number. Make one of them a double when you want the decimals.
Overflow: an int has a ceiling
System.out.println(Integer.MAX_VALUE);        // 2147483647
System.out.println(Integer.MAX_VALUE + 1);    // -2147483648   it wraps around, no error
System.out.println(Integer.MAX_VALUE + 1L);   // 2147483648    long has room
Java never warns you about overflow. Use long for big counts and money in paise.
A char is a number
System.out.println('A' + 1);            // 66   arithmetic turns it into an int
System.out.println((char) ('A' + 1));   // B    cast it back to see the letter
System.out.println((int) 'a');          // 97
Characters are stored as their Unicode numbers; 'A' is 65.
null is only for references
String s = null;      // fine: "points at nothing yet"
int[] a = null;       // fine
int n = null;         // compile error: incompatible types: <null> cannot be converted to int
A primitive always holds a value; there is no "nothing" number.
Wrapper classes: a primitive inside an object
Integer boxed = 5;                    // int wrapped into an object (autoboxing)
int plain = boxed;                    // and unwrapped again
List<Integer> list = List.of(1, 2);   // collections hold objects, so Integer, not int
System.out.println(boxed + plain + list.size());   // 12
Each primitive has a wrapper (Integer, Double, Character…) for places that need an object.
Limits worth knowing
System.out.println(Byte.MAX_VALUE);             // 127
System.out.println(Short.MAX_VALUE);            // 32767
System.out.println((int) Character.MAX_VALUE);  // 65535
System.out.println(Long.MAX_VALUE);             // 9223372036854775807
System.out.println(0.1 + 0.2);                  // 0.30000000000000004   doubles are approximate
Never use double for money; use long in the smallest unit or BigDecimal.
💡 Remember itA primitive is a number written on the box. A reference is a number plate on the box that says where the car is parked. Copy the first and you have two numbers; copy the second and you have two plates for one car. Strings (Lesson 01) and objects (Lesson 02) are always the second kind.
05

5 interview questions

Answer each one in your head before you open it.

01What is the difference between JDK, JRE and JVM?
The JVM runs bytecode. The JRE is the JVM plus the class library, enough to run programs. The JDK is the JRE plus the development tools (javac, jshell, jar). Developers install the JDK.
02Why is Java called "platform independent"?
javac produces bytecode, not machine code. The same .class file runs on any OS that has a JVM; only the JVM is built per platform.
03How many primitive types are there, and what are they?
Eight: byte short int long (whole numbers), float double (decimals), char (one character), boolean. Everything else is a reference type.
04What is the difference between a primitive and a reference variable?
A primitive variable holds the value itself; copying it copies the value. A reference variable holds the address of an object on the heap; copying it copies the address, so both variables see the same object. References can be null; primitives cannot.
05Where do variables, objects and classes live?
Local variables in a stack frame (one frame per running method); objects on the heap, cleaned up by the garbage collector; loaded classes in Metaspace.
06

Review

5 takeaways

  • Java source is compiled by javac into bytecode; the JVM runs the bytecode on any OS.
  • JDK ⊃ JRE ⊃ JVM. Install the JDK; it contains the other two.
  • The JVM keeps variables on the stack, objects on the heap and classes in Metaspace.
  • Eight primitives hold values; every other type is a reference that holds an object's address and may be null.
  • Copying a primitive copies the value; copying a reference copies the address, so two variables can share one object.
