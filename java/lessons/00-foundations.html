F1

The Java platform: JDK, JRE, JVM and bytecode

In 30 seconds You write Hello.java. javac turns it once into Hello.class: bytecode. That one file runs on Windows, Linux and macOS, because each has its own JVM that reads bytecode. The JVM starts by interpreting it, then compiles the hot parts to machine code (the JIT). JDK = the tools to write Java · JRE = what is needed to run it · JVM = the engine inside both.

💡 Remember itBytecode is sheet music. javac writes it down once. Every JVM is a musician who reads the same sheet on their own instrument (the CPU), and a piece played often is learned by heart: that is the JIT.

Go deeper: what the bytecode looks like (javap -c Add)

JDK 25 writes class-file version 69. Bytecode is a tiny stack machine: push values, operate, pop the result.

static int add(int, int);
  Code:
     0: iload_0            // push parameter a onto the operand stack
     1: iload_1            // push parameter b
     2: iadd               // pop both, push a + b
     3: ireturn            // return the int on top of the stack

public static void main(java.lang.String[]);
  Code:
     0: iconst_2
     1: iconst_3
     2: invokestatic  #7   // Method add:(II)I
     5: istore_1           // store the result in local slot 1 (sum)
     ...
    10: invokedynamic #19  // makeConcatWithConstants: "2 + 3 = " + sum (Java 9+)
  • Locals live in numbered slots: a is slot 0 because add is static (an instance method keeps this in slot 0).
  • invokestatic pushes a new frame on the thread's stack for add; ireturn pops it (F5 shows the frames).
  • String + compiles to invokedynamic since Java 9 (Lesson 02, D8).

Common mistakes: running java Add.class (the launcher wants the class name: java Add); naming the file differently from its public class (compile error); thinking Java is "only interpreted" (hot code is compiled to native code while it runs); and thinking bytecode is tied to an OS (it is not, but a newer class-file version will not run on an older JVM: UnsupportedClassVersionError).
Interview answer

"The JDK is the development kit: the compiler and tools plus a runtime. The JRE is the runtime: the JVM plus the standard libraries. The JVM executes bytecode. javac compiles source into platform-neutral bytecode; at run time the class loader loads classes on demand, the verifier checks them, and the JVM interprets them while the JIT compiles hot methods into native code. That is why Java is portable and still fast."

Follow-ups
  • Is Java compiled or interpreted? — Both: compiled to bytecode ahead of time, then interpreted and JIT-compiled at run time.
  • Why does a Java app get faster after warm-up? — The JIT compiles hot methods using profiling data (inlining, escape analysis).
  • What is UnsupportedClassVersionError? — The class was compiled for a newer Java than the JVM running it. Use javac --release N.
  • Is the JVM platform-independent? — No. Bytecode is; each OS/CPU needs its own JVM build.
F2

Variables and types: primitives vs references

In 30 seconds Java has 8 primitive types that hold a value directly (int, double, boolean…), and reference types (every class, interface and array) whose variables hold a reference to an object on the heap. Each primitive has a wrapper class (int ↔ Integer), and Java converts between them automatically: autoboxing.

This visualisation needs JavaScript.

Why it exists: primitives are fast and small (no object header, no garbage collection). Objects give you methods, null and the ability to live in collections like List<Integer>. Java keeps both and bridges them with wrappers.

Defaults apply only to fields and array elements. A local variable has no default: the compiler refuses to read it until it is definitely assigned.

  • Boxing line 8: Integer a = 127 becomes Integer.valueOf(127). The cache is required by the spec for −128..127; the upper bound can be raised with -XX:AutoBoxCacheMax, so never rely on == for any value.
  • Boxing line 15: when one side of == is a primitive, the other side is unboxed and the values are compared.
  • Boxing line 22: int n = apples calls apples.intValue(); on null that throws NullPointerException. This is a classic bug with Map<String, Integer>.
Common mistakes: comparing Integer or Long with == (works in tests with small numbers, fails in production with big ones); unboxing a null from a map; writing long x = 3000000000 (error: integer number too large, add L); writing float f = 1.5 (error: possible lossy conversion from double to float, add f); using float/double for money.
Real-world: entity IDs are often Long. if (order.getId() == other.getId()) passes for IDs up to 127 and silently fails after that. Use Objects.equals(a, b) or compare long values.
Interview answer

"Java has eight primitives, which store values directly, and reference types, whose variables store a reference to a heap object. Each primitive has a wrapper, and the compiler autoboxes with valueOf and unboxes with xxxValue(). Two traps: Integer.valueOf caches −128 to 127, so == between wrappers only looks right for small numbers; and unboxing null throws a NullPointerException."

Follow-ups
  • Is Java purely object-oriented? — No, because of primitives; wrappers and autoboxing bridge the gap.
  • Where do primitives live? — Locals live in the stack frame; a primitive field lives inside its object on the heap.
  • Which other wrappers cache? — Byte, Short, Long (−128..127), Character (0..127) and Boolean; Float and Double don't.
  • Why can't generics use int? — Type erasure turns T into Object, so type arguments must be references (Java 25 still requires this).

Operators, casting and arithmetic traps

In 30 seconds Java converts a smaller type to a bigger one automatically (widening), but going smaller needs an explicit cast and can lose data (narrowing). Arithmetic on byte, short and char happens in int. int overflow wraps silently, / on ints drops the fraction, and double can't store 0.1 exactly.

This visualisation needs JavaScript.

Wideningbyte → short → int → long → float → double, and char → intNo. Safe (int → float and long → float/double can lose precision, but not range).
Narrowingthe other way, e.g. int → byte, double → intYes. Integers keep the low bits; doubles truncate toward zero.

  • Line 8: 300 is 0001 0010 1100 in binary. A byte keeps the low 8 bits 0010 1100 = 44.
  • Line 14: MAX_VALUE + 1 wraps to MIN_VALUE (two's complement). No exception. Cast one operand to long before the operation, or use Math.addExact.
  • Lines 22–24: % takes the sign of the left operand. For "wrap into 0..n−1" (circular buffers, hash buckets) use Math.floorMod.
Common mistakes: int mid = (lo + hi) / 2 can overflow for huge indexes (use lo + (hi - lo) / 2); double avg = sum / count with two ints is already truncated (cast first: (double) sum / count); k = k++ leaves k unchanged; new BigDecimal(0.1) keeps the binary error (use the String constructor or BigDecimal.valueOf); comparing doubles with ==.
Real-world: money is stored as BigDecimal or as a long number of cents, never as double. Timestamps in milliseconds need long (an int overflows after about 24.8 days of milliseconds).
Interview answer

"Widening conversions are implicit and safe; narrowing needs a cast and keeps only the low bits or truncates. Integer arithmetic is done in at least int and overflows silently, so I use long or Math.addExact where it matters. Compound operators like += include a hidden cast, which is why b += 1 compiles for a byte but b = b + 1 doesn't. For money I use BigDecimal built from a String, because double is binary floating point."

Follow-ups
  • What is Integer.MIN_VALUE == -Integer.MIN_VALUE? — true: negating it overflows back to itself. Math.abs(Integer.MIN_VALUE) is negative too.
  • Difference between & and &&? — && skips the right side when the left is false; & always evaluates both (and is also bitwise AND on ints).
  • What is 1.0 / 0? — Infinity. 1 / 0 throws ArithmeticException.

Control flow: if, switch and loops

In 30 seconds if/else picks a branch, switch picks one of many cases, and for, while, do-while and the enhanced for repeat code. The classic switch falls through without break. The modern arrow form (Java 14+) never falls through and can return a value; Java 21 adds pattern matching on types.

F5

Methods, overloading, scope and recursion

In 30 seconds A method is a named block with parameters and a return type. Its signature is the name plus the parameter types (not the return type). Several methods can share a name if their parameters differ: overloading, resolved at compile time. Every call pushes a frame on the thread's stack; recursion is a method calling itself, and without a base case the stack overflows.

The compiler resolves an overloaded call in three phases and stops at the first phase that finds a match: (1) exact match or widening, no boxing; (2) boxing/unboxing allowed; (3) varargs allowed. Inside a phase, the most specific method wins. That is why show(5) picks long over Integer: widening is phase 1, boxing is phase 2.

The exact depth before StackOverflowError depends on the stack size (-Xss), the frame size and the JIT, so the program only prints "thousands of" frames.

Common mistakes: thinking a different return type alone makes an overload (it doesn't: compile error); expecting overloading to pick by the runtime type of an argument (it uses the compile-time type; overriding is the runtime one); recursion without a reachable base case; deep recursion on big inputs (Java has no tail-call optimisation, so a loop or an explicit stack is safer); catching StackOverflowError as normal control flow.
Interview answer

"A method's signature is its name and parameter types. Overloading means same name, different parameters, and the compiler chooses the method at compile time: first exact or widening matches, then boxing, then varargs. Each call creates a stack frame holding its parameters and locals; recursion stacks frames until a base case returns, and too many frames give a StackOverflowError, which is an Error, not an Exception."

Follow-ups
  • Overloading vs overriding? — Overloading: same class, different parameters, compile time. Overriding: subclass, same signature, chosen at run time by the object's class.
  • Can main be overloaded? — Yes, but the launcher calls main(String[]) (Java 25 also accepts an instance main()).
  • StackOverflowError vs OutOfMemoryError? — One thread's stack is full vs the heap (or Metaspace) is full.
  • When is recursion a bad idea? — Deep inputs (linked lists of a million nodes) or overlapping subproblems without memoisation.

F6

Pass-by-value: what really happens to arguments

In 30 seconds Java always passes a copy of the variable. For a primitive that copy is the number. For an object it is a copy of the reference, so the method can change the object the reference points to, but it can't make the caller's variable point somewhere else.

This visualisation needs JavaScript.

Analogy: you give a friend a photocopy of your house address. They can go to the house and repaint it (you'll see the new paint). If they cross out the address on their copy and write a new one, your copy still has your address.
  • addTen: x is a separate int; the caller's n stays 5.
  • deposit: acc and a hold the same reference, so acc.balance += 10 changes the one shared object.
  • replace and swap: they only reassign their own copies. If Java were pass-by-reference, swap would work; it doesn't.
  • grow: StringBuilder is mutable, so append is visible. String is immutable, so s + "!" makes a new object that only the local copy points to.

The same rule with arrays (a method that changes elements vs one that assigns a new array) is drawn in A8 · Arrays and methods.

Common mistakes: saying "objects are passed by reference" (the reference is passed by value); expecting a method that reassigns a String or Integer parameter to change the caller's variable; forgetting that a method can mutate a list or array you pass in (make a defensive copy if it must not).
Interview answer

"Java is strictly pass-by-value. For primitives the value is the number; for objects the value is the reference. So a method can mutate the object through its copy of the reference, and the caller sees that, but reassigning the parameter only changes the local copy. The proof is that a swap(a, b) method can't swap the caller's variables."

Follow-ups
  • Why doesn't changing a String parameter affect the caller? — Strings are immutable; every "change" creates a new object and only the local copy points to it.
  • How do you return two values then? — Return an object or a record, or (less clean) mutate a passed-in holder.
  • Is a copy of a reference expensive? — No, it is one word (4 or 8 bytes); the object itself is never copied.

Packages, imports, input/output and the command line

In 30 seconds A package groups related classes and matches a folder path (com.shop.util → com/shop/util/). import only saves typing: it lets you write Scanner instead of java.util.Scanner. java.lang (String, Math, System…) is imported automatically. A program starts in main(String[] args), reads input with Scanner or BufferedReader, and writes to System.out and System.err.
💡 Remember itSystem.out and System.err are two separate pipes: results flow through one, alarms through the other, and a shell can send each pipe somewhere different.

F8

Foundations: interview questions and review

01What is the difference between the JDK, JRE and JVM?
JVM runs bytecode. JRE = JVM + standard libraries (enough to run). JDK = JRE + development tools such as javac, javap and jshell.
02Why is Java called platform independent?
javac produces bytecode, not machine code. Any OS with a JVM can run the same .class file. The JVM itself is platform-specific.
03What does the JIT compiler do?
It watches which methods run often and compiles them to optimised native code at run time (HotSpot: C1, then C2), so long-running Java code runs close to C speed.
04Name the 8 primitive types and their sizes.
byte 8, short 16, int 32, long 64, float 32, double 64, char 16 (unsigned) bits, and boolean (size not specified by the language).
05Why does Integer a = 128, b = 128; a == b print false?
Autoboxing calls Integer.valueOf, which caches only −128..127. 128 creates two objects, and == compares references. Use equals.
06Do local variables get default values?
No. Fields and array elements do. Reading an unassigned local is a compile error: variable might not have been initialized.
07Why does byte b = 10; b += 1; compile but b = b + 1; doesn't?
b + 1 is an int. Compound assignment includes an implicit cast back to the variable's type: b = (byte) (b + 1).
08What is Integer.MAX_VALUE + 1?
Integer.MIN_VALUE (−2147483648). Integer overflow wraps silently. Use long or Math.addExact.
09Why should you not use double for money?
It is binary floating point, so 0.1 can't be stored exactly (0.1 + 0.2 is 0.30000000000000004). Use BigDecimal from a String, or a long of cents.
10What is the difference between a switch statement and a switch expression?
The expression (Java 14+) uses ->, never falls through, must be exhaustive and returns a value (yield inside a block). The classic statement falls through without break.
11How does the compiler choose between overloaded methods?
In three phases: exact/widening without boxing, then boxing, then varargs; the most specific match in the first successful phase wins. It uses compile-time types.
12Is Java pass-by-value or pass-by-reference?
Always pass-by-value. For objects the value is a reference, so the method can mutate the object but can't reassign the caller's variable. A swap method proves it.

5 takeaways

  • javac → bytecode → JVM (class loader, verifier, interpreter, JIT). Bytecode is portable; the JVM is not.
  • 8 primitives hold values; everything else is a reference to a heap object. Locals have no defaults.
  • Wrappers cache −128..127, so compare them with equals, and never unbox a possible null.
  • Arithmetic is at least int, overflow wraps, / truncates, % follows the left sign, and money is BigDecimal.
  • Overloading is chosen at compile time; every call is a stack frame; Java passes copies, including copies of references.
