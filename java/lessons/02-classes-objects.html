LESSON 02 · CLASSES AND OBJECTS

What is a Class, and what is an Object?

The idea the whole of Java is built on, explained properly: a class is the blueprint, an object is the real thing built from it. You will see what is inside a class, what new really does, where objects live in memory, what a reference is, how constructors and this work, what static means, and how to print and compare objects. Build cars in the factory, drive them, copy their keys; run every program.

LESSON 02

Classes and objects: the blueprint and the thing

Ten short sections. Each one has a picture or lab you can play with, a program you can run, and a question an interviewer actually asks.

01

What is a class? What is an object?

In 30 seconds A class is a blueprint: it describes what every thing of that kind has (its fields, the data) and what it can do (its methods, the behaviour). An object is one real thing built from that blueprint with new. One class, as many objects as you like, and each object has its own copy of the fields.

Think about a car. Every car has a model, a colour and a speed, and every car can accelerate and honk. Writing that description down once is the class. The red Swift in your parking lot and the blue Nexon next to it are objects: two real cars, built from the same description, each with its own colour and its own speed.

💡 Remember itA class is the blueprint of a car: one drawing. An object is a real car built from it in the factory (new). You can't drive a blueprint, and one blueprint builds any number of cars. A variable is the car key: copying a key does not build a second car.

02

Inside a class: fields, constructors, methods

A class body holds members. You will meet three kinds all the time:

MemberWhat it isIn CarRule of thumb
Field (instance variable)Data each object storesString model; int speed;A noun: what it has
ConstructorCode that sets up a new object; same name as the class, no return typeCar(String model, String color) { … }Runs once per object, inside new
MethodBehaviour; reads and changes this object's fieldsvoid accelerate(int by) { … }A verb: what it does

A class is also a new type, exactly like int or String. Once Car exists you can declare Car variables, pass a Car to a method, return one, and keep them in an array.

File rules: a public class Car must be in a file named Car.java, and a file has at most one public top-level class. The static class Car inside Garage is a nested class: a handy way to keep a small example in one file. Class names are nouns in PascalCase; fields and methods are camelCase.

The dot does the work: c.model reads this object's field, a.accelerate(40) runs the method on object a. The method code is the same for every car; the data it touches is the one object you called it on.

03

What new really does

In 30 seconds new Car("Swift") does three things, in order: 1 allocate memory for a new Car on the heap, with every field at its default value; 2 run the constructor on that object (this = the new object); 3 hand back a reference to it, which you store in a variable.
💡 Remember itThe factory first builds a bare car (no paint, speed 0), then the workers (the constructor) paint it and fit the badge, then you get the key.

Watch it run

Step through it: the object appears with default values, the constructor frame gets this, the reference comes back, then a reference is copied and re-pointed.

Step 1 is why fields always start with a value, even if the constructor never sets them. Local variables (inside a method) get no default: the compiler refuses to let you read one before you assign it.

04

Where objects live: stack, heap, Metaspace

In 30 seconds Every object lives on the heap. A variable of a class type never holds the object: it holds a reference (an arrow) to it. Local variables sit in the method's frame on the stack. The class itself (its field layout and method code) is loaded once into Metaspace, and every object points back to it.

Because a variable only holds a reference, Car c = a; copies the arrow, not the car. Change the car through c and a sees it. Set a variable to null and it points at nothing; call a method through it and you get a NullPointerException. Drive the heap yourself:

Pass-by-value, again: just like the String in Lesson 01, tune(c) gets a copy of the reference. Following the copy (car.speed = 100) changes the caller's car; re-pointing the copy (car = new Car(…)) changes nothing for the caller. Java has no pass-by-reference.

When does an object die? You never delete objects in Java. When no reachable variable refers to an object any more, it becomes eligible for garbage collection, and the garbage collector frees it whenever the JVM decides (System.gc() is only a request).

05

Constructors and this

In 30 seconds A constructor has the class's name and no return type; it runs once per object, inside new, to put the object in a valid state. Write no constructor and the compiler adds an empty no-argument one; write any constructor and it doesn't. this is the reference to the current object: this.model = model sets the field from the parameter. this(…) calls another constructor of the same class.
RuleDetail
Name and return typeSame name as the class, no return type. void Car() {} is a method called Car, not a constructor.
Default constructorAdded by the compiler only when the class declares no constructor at all.
OverloadingSeveral constructors with different parameter lists. Put the real work in one and let the others call it with this(…).
this(…)Calls another constructor of the same class; it must be the first statement.
this (no brackets)The current object. Needed when a parameter shadows a field with the same name.
The classic bug: in Bike, model = model; assigns the parameter to itself, because inside the constructor the name model means the parameter. The field stays null. Write this.model = model;.
06

static vs instance: the class's data vs each object's data

In 30 seconds An instance field belongs to each object: every car has its own speed. A static field belongs to the class: there is exactly one copy, shared by all objects, and it exists even before any object. A static method runs without an object, so it has no this and can't touch instance fields directly. That is why main is static: the JVM calls it before any object exists.
💡 Remember itEach car has its own odometer (instance). The factory has one counter on the wall of how many cars it has built (static). Every car can read the wall, but there is only one wall.

07

Printing and comparing objects

In 30 seconds Every class quietly extends Object, so every object already has toString(), equals() and hashCode(). println(obj) calls toString(); the default prints ClassName@hexHash. The default equals is the same as ==: "same object?". Override them to say what your object looks like and what "equal" means; if you override equals, always override hashCode too.

This is the same rule you met with Strings in Lesson 01: == compares identity (the arrows), equals compares content. String already overrides equals; your own classes must do it themselves. (Lesson 01's twins are back: two Cars with the same model and year are twins, not one car.)

10 interview questions

Answer out loud first, then open the card.

01What is a class, and what is an object?
A class is a blueprint (a user-defined type) that declares state (fields) and behaviour (methods). An object is an instance of that class created at run time with new; it lives on the heap and has its own copy of the instance fields.
02What is the difference between a class and an object?
A class is a logical template, written once and loaded once; it takes no heap memory for instance data. An object is a physical instance: you can create many from one class, each on the heap with its own state, its own identity, and the class's behaviour.
03What happens when you write new Car("Swift")?
The JVM (loads the class if needed and) allocates memory on the heap with every field at its default value, runs the constructor with this = the new object, and returns a reference to it, which is stored in the variable.
04Where are objects stored? Where are references stored?
Objects always live on the heap. A local reference variable lives in its method's stack frame; a reference held in a field lives inside the object that owns the field (on the heap). Class metadata and method code are in Metaspace.
05Does Car c = a; create a new object?
No. It copies the reference, so a and c point to the same object and a == c is true. A change through one is visible through the other.
06What are the default values of fields? Do local variables get them?
Numbers 0 / 0.0, boolean false, char character 0, references null. Local variables get no default; reading one before assigning it is a compile error.
07What is a constructor? How is it different from a method?
Code that initialises a new object: it has the class's name, no return type, runs once per object inside new, and is not inherited. A method has a return type (or void), any name, and can be called any number of times on an existing object.
08What is this?
A reference to the current object, available in constructors and instance methods. Used to reach a field shadowed by a parameter (this.model = model), to call another constructor (this(…)), or to pass the current object somewhere. Static methods have no this.
09What is the difference between static and instance members?
Instance members belong to each object (one copy per object, need an object to use). Static members belong to the class (one shared copy, used via the class name, exist before any object). A static method has no this, so it can't use instance fields directly.
10In how many ways can you create an object in Java?
The usual answer is five: new; reflection (Car.class.getDeclaredConstructor().newInstance()); clone(); deserialization; and factory methods such as List.of() or LocalDate.now(), which use one of the others inside. new is the one you use every day.
10

Review

5 takeaways

  • A class is the blueprint (fields + constructors + methods) and a new type; an object is one real instance built from it with new.
  • new allocates the object on the heap with default values, runs the constructor, and returns a reference.
  • Variables hold references, not objects: copying a variable shares the object, null means no object, and unreachable objects are garbage-collected.
  • Constructors set up the object; this is the current object. Static members belong to the class, instance members to each object.
  • println calls toString(); == asks "same object?", equals asks "same content?" once you override it (with hashCode).
