Time and space complexity

Before any data structure or algorithm, you need one skill: telling how much work and how much memory a piece of code needs as its input grows. Every interview answer ends with "this is O(n) time and O(1) space", and every solution is judged by it. This lesson builds the skill from zero, with a moving picture for each idea, and ends with real interview questions from Amazon, Google, Meta and Microsoft.

00

What "fast" means: count steps, not seconds

In 30 seconds A program is a list of instructions. To say how fast it is, we do not use a clock. We count the steps it takes. Then we ask one question: if the input becomes twice as big, what happens to the number of steps? The answer to that question is what this lesson calls complexity.

The problem it solves. Sharma Motors has a lot full of cars, and every number plate is under a cover. A customer asks for the car with plate KA05. A helper walks along the lot and lifts one cover after another. How long does that take? Asha lifts a cover in 1 second. Ravi needs 3. On a rainy day both are slower. "How many seconds?" has a different answer for every person and every day. "How many covers must be lifted?" has one answer, whoever does the lifting.

Four words first. An algorithm is a fixed list of instructions for a job: "start at bay 0, lift the cover, is it KA05? If not, go to the next bay." The input is the data the algorithm is given: here, the lot of cars. n is the size of the input: the number of cars. A step is one small action that takes about the same time every time it is done: lifting one cover and reading one plate.

Why ask how the count grows? A count for one lot ("6 steps for 6 cars") says little, because every method is quick on 6 cars. Sharma Motors will not stay at 6 cars. This method takes at most n steps for n cars, so twice the cars means twice the steps. Other methods grow in other ways: some need four times the steps when the input doubles, some need only one step more. That pattern of growth, and not the seconds, decides which method still works with 1 lakh cars.

Common mistake Timing one run with a stopwatch and calling the code fast. One run, on one small input, on your own laptop says nothing about 1 lakh cars on a busy server. Count the steps, then ask how the count grows.
💡 Remember itA drive from Bengaluru to Mysuru. "How long does it take?" depends on the car and the traffic. "How many kilometres is it?" does not. Steps are the kilometres of a program: the same for every driver, and twice the distance is always twice the kilometres.
Go deeper: what exactly is one step, and do seconds never matter?

A step is anything that takes about the same time however big the input is: one comparison, one addition, reading one array slot. Lifting a cover is really three small actions (lift, read, compare). Counting it as 1 or as 3 changes the total from n to 3n, but not the growth: twice the cars is still twice the steps. That is why section 04 drops such constant factors.

Seconds do matter in the end, and you get them back by multiplying: seconds = steps × time per step. This course uses the round figure of 10⁸ simple steps per second (section 11). You can also time code in Java with System.nanoTime(), but the number changes from run to run, so it is a check on your step count and not a replacement for it.

01

The problem: a search that times out

In 30 seconds Two programs can give the same answer while one takes 1 second and the other 3 hours. Seconds depend on the machine, so we measure something that doesn't: the number of basic steps the code takes, written as a function of the input size n (the number of cars, items, characters…). Time complexity is how that step count grows as n grows. Space complexity is the same idea for extra memory.

The case. Sharma Motors' website has a "find duplicate listings" check: before a car goes live, the code compares it against every listing. With 100 cars the page answered instantly. The company bought two other dealerships and the list grew to 1 lakh (100,000) cars. Now the check takes so long that the page times out. The same code, the same server: only n changed. By section 10 you will know exactly why, and you will fix it.

Why not just measure seconds? A fast laptop, a slow phone and a busy server give different seconds for the same code. What does not change is how many basic steps the code does. A step is any small operation that takes about the same time whatever the input: reading a[i], comparing two numbers, adding, assigning. We count steps, and we care about one question: when n doubles, what happens to the step count?

💡 Remember itAsking "how long does checking the lot take?" has no answer: it depends on who walks. Asking "how many cars must be checked?" always has one. Complexity counts cars checked, not minutes.

02

The only maths you need

In 30 seconds Four facts cover almost every complexity. Powers: 2ⁿ means 2 × 2 × … n times (2¹⁰ = 1,024). Logarithm: log₂ n is how many times you can halve n before reaching 1 (log₂ 1,024 = 10). Staircase: 1 + 2 + … + n = n(n+1)/2, about n²/2. Doubling sum: 1 + 2 + 4 + … + n is less than 2n.

Powers grow by multiplying: 2⁵ = 32, 2¹⁰ = 1,024 ≈ a thousand, 2²⁰ ≈ a million, 2³⁰ ≈ a billion. Remember those three: they come up all the time.

Logarithms are powers in reverse. 2¹⁰ = 1,024, so log₂ 1,024 = 10. In plain words: log₂ n = the number of times you can halve n until 1 is left. So log₂ of a thousand ≈ 10, of a million ≈ 20, of a billion ≈ 30. The log grows very slowly: a thousand times more data adds only 10 steps. In complexity we write just "log n": log₂, log₃ and log₁₀ differ only by a constant factor, and constants are dropped (section 04).

The staircase: a loop whose step i does i things costs 1 + 2 + … + n = n(n+1)/2. Draw it and it is half of an n × n square, so it grows like n². The doubling sum: 1 + 2 + 4 + … + 2ᵏ = 2ᵏ⁺¹ − 1, less than twice the last term. Both show up again in sections 05 and 09.

03

The growth classes, from fast to hopeless

In 30 seconds Almost every algorithm falls into one of seven classes. Read O(f(n)) ("big O of f of n") as "the number of steps grows like f(n)"; section 04 makes that exact. From best to worst: O(1) constant, O(log n) logarithmic, O(n) linear, O(n log n), O(n²) quadratic, O(2ⁿ) exponential, O(n!) factorial. Where does 2ⁿ come from? A method that calls itself

A method may call itself; this is called recursion. It must have a base case, an input small enough to answer directly, or it would call itself forever. The classic example is the Fibonacci numbers 0, 1, 1, 2, 3, 5, 8…, where each number is the sum of the two before it. 04

Big-O and its two rules

In 30 seconds Big-O describes how the step count grows for large n, as an upper bound. Two rules: drop constant factors (3n + 5 → O(n), 100n → O(n)) and keep only the biggest term (n² + n → O(n²)). For large n, the growth rate decides everything.

Writing "this code takes 3n + 5 steps" is precise but not useful: the 3 and the 5 depend on how you count and on the machine. What stays true is the shape: it grows in a straight line with n. Big-O keeps the shape and throws away the rest. Formally, f(n) is O(g(n)) if, beyond some n, f(n) ≤ c · g(n) for some constant c: f grows no faster than g.

  • Drop constants: 2n, n + 7, 100n are all O(n). n/2 is O(n) too.
  • Keep the biggest term: n² + n + 1 is O(n²); n + log n is O(n); 2ⁿ + n³ is O(2ⁿ).
  • Different inputs keep different letters: walking n cars and m branches is O(n + m), not O(n).

This visualisation needs JavaScript.

When do constants matter? For small n, and between two solutions of the same class. An O(n) loop that does 50 things per car can lose to another O(n) loop that does 2. Interviewers sometimes ask exactly this follow-up.

05

In 30 seconds Loops one after another add; loops inside each other multiply. A loop variable that doubles or halves gives log n. Method calls count too. A loop that calls a method costs (loop count) × (cost of the method). for (i < n) list.contains(x) is n × n = O(n²) when contains walks the list. Section 12 lists the costs of the Java methods you will use most.

06

What O(log n) looks like

In 30 seconds An algorithm is O(log n) when each step throws away a fixed fraction (usually half) of what is left. The classic is binary search on sorted data: check the middle, keep the half that can still hold the answer. 1,000,000 cars need at most 20 checks.

Picture the cars sorted by price on a long row. You want the ₹18 lakh car. Walking from the start could take every car. Instead, look at the middle car: if it is cheaper than 18, the target cannot be on its left, so half the row is gone with one check. Repeat on the half that is left. The data must be sorted, or throwing half away would be wrong. D07 is a full lesson on binary search.

07

Best, average and worst case; O, Ω and Θ

In 30 seconds The same code can take different numbers of steps on different inputs of the same size. Best case = the luckiest input, worst case = the unluckiest, average case = the expected count over all inputs. Interviews quote the worst case unless they say otherwise. O is an upper bound, Ω a lower bound, Θ both at once (a tight bound).

In everyday interview talk, people say "O(n)" when they mean the tight worst case. That is fine; just know the difference if asked.

08

Space complexity

In 30 seconds Space complexity counts the extra memory an algorithm needs as n grows, beyond the input it was given (called auxiliary space). A few variables: O(1). A new array or set of n items: O(n). Recursion also uses memory: one stack frame per call that is still waiting, so a call chain n deep is O(n) space.

Where memory lives in Java. The stack holds each running method's local variables (int i, int tmp, references); it is freed when the method returns. The heap holds arrays and objects created with new. Extra space means what your method adds to either one.

This visualisation needs JavaScript.

  • The input is not counted as extra space, unless the question says "total space".
  • The output can be. If you must return a new array of n items, say so: "O(n) for the output, O(1) besides".
  • Recursion is not free. fib(n) from section 03 is at most n calls deep at any moment, so it uses O(n) stack space, even though it makes O(2ⁿ) calls in total. Too deep, and Java throws StackOverflowError.
09

Amortized O(1): the doubling array

In 30 seconds An ArrayList is Java's growable list, built on an array. When the array is full it makes one twice as big and copies everything: that single add is O(n). Copies are rare, and the doubling sum (section 02) shows the total copying for n adds is under 2n. So the average cost per add is constant: amortized O(1).

An array's length is fixed (Java Lesson 10). java.util.ArrayList hides an array inside and grows it for you: list.add(x), list.get(i), list.size(). "Amortized" means averaged over a long run of operations: an occasional expensive step is paid for by many cheap ones, like a car's yearly service spread over every kilometre.

This visualisation needs JavaScript.

The real ArrayList grows by 1.5× instead of 2×; any constant factor greater than 1 gives the same amortized O(1).

10

The fix: trade memory for time

In 30 seconds The duplicate check compared every pair of cars: n(n−1)/2 ≈ 5 billion comparisons at 1 lakh cars, O(n²) time, O(1) space. Remembering every VIN seen so far in a HashSet answers "seen it before?" in about one step: O(n) time, O(n) space. Spending memory to save time is the most common optimisation in interviews.

A HashSet in one paragraph. java.util.HashSet is a box of distinct values. set.add(x) puts x in and returns false if x was already there; set.contains(x) asks "is x inside?". Both take about one step on average, whatever the size, because the set computes where x must be stored instead of searching. D02 shows how. For now: a seen box with an O(1) question.

Measuring time in Java. System.nanoTime() reads a stopwatch in nanoseconds. Read it before and after, subtract, divide by 1,000,000 for milliseconds. Times change between runs, so trust big differences only.

Case closed. Sharma Motors swapped the nested loops for the seen box. At 1 lakh cars the check fell from seconds to about 10 ms, and it now grows in a straight line with the stock. The price: memory for 1 lakh VINs, a few megabytes. That trade is almost always worth it.

Read the constraints: what complexity do you need?

In 30 seconds Every interview and coding-test problem states a limit on n. With about 10⁸ simple steps per second and a 1–2 second limit, the limit tells you the target before you write any code: n ≤ 10 → n! is fine; ≤ 20 → 2ⁿ; ≤ 500 → n³; ≤ 5,000 → n²; ≤ 10⁶ → n log n; bigger → O(n), O(log n) or O(1).

Two Sum LC 1EasyTime O(n) · Space O(n) AmazonGoogleMetaMicrosoftAppleBloombergAdobeUberFlipkart

Problem. Given an array of numbers and a target, return the indexes of the two numbers that add up to the target (exactly one answer exists). At Sharma Motors: a customer has exactly ₹9 lakh for two cars; which two?

Brute force: try every pair, O(n²) time. Observation: for each price p, the partner must be exactly target − p. Instead of searching for it, remember every price seen so far with its index in a HashMap (a HashSet that also stores a value per key: here price → index). Optimal: one pass, O(n) time, O(n) space.

Follow-ups: "What if the array is sorted?" (two pointers, O(1) space: D03) · "Return all pairs?" · "Why not sort first?" (sorting loses the original indexes and costs O(n log n)).

Missing Number LC 268EasyTime O(n) · Space O(1) AmazonGoogleMetaBloombergMicrosoftApple

Problem. An array holds n distinct numbers from 0 to n; one is missing. Find it. At Sharma Motors: service tokens 0…n were handed out and one never came back.

Brute force: for each x from 0 to n, scan the array: O(n²). Better: a HashSet, O(n) time but O(n) space. Observation: the staircase from section 02! 0 + 1 + … + n = n(n+1)/2, so the missing number is that total minus the actual sum. Optimal: O(n) time, O(1) space. The interviewer is checking whether you push past the HashSet answer.

Follow-ups: "Can the sum overflow?" (use long, or XOR all indexes and values: D19) · "Two numbers missing?"

Best Time to Buy and Sell Stock LC 121EasyTime O(n) · Space O(1) AmazonGoogleMetaMicrosoftAppleAdobeBloombergFlipkartUber

Problem. prices[i] is the price on day i. Buy on one day and sell on a later day; return the best profit (0 if none). At Sharma Motors: the trade-in price of a used car, day by day.

Brute force: every buy day × every later sell day: O(n²). Observation: if you sell today, the best buy day is simply the cheapest day so far. Keep that one number as you walk. Optimal: one pass, O(n) time, O(1) space.

Follow-ups: "Many trades allowed?" (LC 122, greedy: D16) · "At most two trades?" (LC 123, DP: D18) · "Return the days, not the profit?"

Practice: 15 problems and the speed drill

In 30 seconds Five easy, five medium and five hard "find the time and space complexity" problems in the style interviewers use as follow-ups. Answer out loud, open the hint if you are stuck, then the worked answer. Then run the timed drill until you score 9 / 10.

Easy

E1for (i < n) for (j < 5) c++;

Hint: how many times does the inner loop run, and does it depend on n?

Answer: O(n) time, O(1) space. 5n steps; 5 is a constant.

E2Print the first 10 cars of a list of n cars.

Hint: does the work change when n goes from 100 to a million?

Answer: O(1). Always 10 steps (assuming n ≥ 10).

E3while (n > 0) { digits++; n /= 10; }

Hint: n shrinks by a factor each time.

Answer: O(log n) (log₁₀ n, the number of digits). The base doesn't matter in Big-O.

E4A loop over n, then a separate loop over n, then one over n again.

Hint: one after another adds.

Answer: O(n). 3n steps.

E5for (i < n) for (j < n) { c++; break; }

Hint: how many times does the inner body really run per i?

Answer: O(n). The break leaves the inner loop after one step, so n × 1. Read the code, not just its shape.

Medium

M1for (int i = 1; i < n; i *= 2) for (int j = 0; j < i; j++) c++;

Hint: add up the inner counts: 1 + 2 + 4 + … Which sum from section 02 is that?

Answer: O(n). The doubling sum is less than 2n. Many people say O(n log n) here; that is the trap.

M2for (int i = n; i > 0; i /= 2) for (int j = 0; j < n; j++) c++;

Hint: the outer loop halves; the inner loop is always n.

Answer: O(n log n). log n rounds × n each.

M3while (!list.isEmpty()) list.remove(0); on an ArrayList of n

Hint: what does removing the front do to the others?

Answer: O(n²). Each removal shifts the rest: (n−1) + (n−2) + … = the staircase. Removing from the end instead would be O(n) in total.

M4for (int i = 0; i < s.length(); i++) set.add(s.substring(i));

Hint: what does substring cost?

Answer: O(n²) time and O(n²) space. Suffix i has n − i characters, copied and stored: the staircase again.

M5int[][] grid = new int[n][n]; then one pass over it

Hint: count the cells.

Answer: O(n²) time and O(n²) space. n² cells are created and visited.

Hard

H1for (int i = 1; i <= n; i++) for (int j = 0; j < n; j += i) c++;

Hint: the inner loop runs n/i times. Add n/1 + n/2 + n/3 + … + n/n.

Answer: O(n log n). n × (1 + 1/2 + 1/3 + … + 1/n), and that "harmonic sum" grows like log n. This pattern appears in the sieve of primes (D19).

H2void f(int n) { if (n <= 1) return; f(n / 2); }

Hint: how deep does the chain of calls go?

Answer: O(log n) time and O(log n) stack space. One call per halving, and they are all waiting on the stack at the deepest point.

H3void f(int n) { if (n <= 1) return; for (i < n) c++; f(n / 2); }

Hint: the work per call is n, then n/2, then n/4…

Answer: O(n) time, O(log n) space. n + n/2 + n/4 + … < 2n (the doubling sum read backwards).

H4n model names, each up to L letters; sort the letters of every name.

Hint: two different sizes: keep both letters.

Answer: O(n · L log L) time. n sorts, each of L letters. Writing O(n log n) here loses marks.

H5For every number from 1 to n, check whether it is prime by trying divisors up to its square root.

Hint: each check is O(√k) for k up to n.

Answer: O(n√n). Up to n checks of up to √n steps. The sieve in D19 does it in O(n log log n).

12 interview questions

Answer out loud first, then open the card.

01What is time complexity, and why not just measure seconds?
How the number of basic steps grows with the input size n. Seconds depend on the machine, the language and what else is running; the growth rate doesn't, so it compares algorithms fairly and predicts what happens when n grows.
02What is the difference between O, Ω and Θ?
O is an upper bound (grows at most like), Ω a lower bound (at least like), Θ a tight bound (both). Linear search: O(n), Ω(1), and its worst case is Θ(n). In practice "O" is used to mean the tight worst case.
03Why do we drop constants? Do they ever matter?
For large n the growth rate dominates: 100n beats n² beyond n = 100. Constants matter for small n and between two solutions of the same class (for example memory access patterns, or 2 vs 50 operations per element).
04What does O(log n) mean? Why is the base of the log not written?
Each step removes a constant fraction of the input, as in binary search; log₂ of a million is about 20. log_a n and log_b n differ by a constant factor (log_a n = log_b n / log_b a), and constants are dropped.
05Nested loops where the inner starts at i + 1: what is the cost?
(n−1) + (n−2) + … + 1 = n(n−1)/2, which is O(n²). Half the square is still quadratic.
06What does space complexity count? Does the input count?
The extra memory the algorithm needs as n grows (auxiliary space): new arrays, collections, and the recursion stack. The input is usually not counted; say "O(1) extra space". Mention the output if you must build one.
07What is amortized O(1)? Give an example.
The average cost per operation over a long sequence. ArrayList.add: when full it copies everything into a larger array (O(n)), but the gaps between copies grow geometrically, so n adds cost O(n) in total, O(1) each on average.
08Is HashMap.get always O(1)?
O(1) on average, assuming a good hash function spreads keys out. If many keys collide in one bucket it degrades; since Java 8 a crowded bucket becomes a balanced tree, so the worst case is O(log n) instead of O(n). D02 explains.
09How much space does a recursive function use?
O(maximum depth) stack frames, plus whatever each call allocates. Naive fib(n) makes O(2ⁿ) calls but is only n deep, so O(n) space. Too deep a recursion throws StackOverflowError.
10The problem says n ≤ 10⁵. What complexity do you aim for?
O(n log n) or better: n² = 10¹⁰ steps is about 100 seconds at 10⁸ steps per second, while n log n ≈ 1.7 million is instant. Say it out loud before coding.
11Give an example of trading space for time.
Duplicate detection: every pair is O(n²) time with O(1) space; a HashSet of seen values is O(n) time with O(n) space. Two Sum with a HashMap is the same trade. Caching and precomputed tables are the general form.
12Why is building a String with + in a loop slow?
Strings are immutable, so each + creates a new String and copies all characters so far: 1 + 2 + … + n = O(n²). StringBuilder appends into a growable buffer: amortized O(1) per append, O(n) total.

Review

5 takeaways

  • Complexity counts steps (time) and extra memory (space) as a function of n, not seconds.
  • Big-O keeps the growth shape for large n: drop constants, keep the biggest term, and give each input its own letter.
  • Loops in a row add, nested loops multiply, halving gives log n; a library call inside a loop multiplies by its own cost.
  • Quote the worst case. Space includes new collections and the recursion stack, not the input. Amortized = averaged over many operations.
  • Read the constraint first (about 10⁸ steps per second), then pick the technique; trading memory for time (a HashSet or HashMap) is the most common optimisation.
